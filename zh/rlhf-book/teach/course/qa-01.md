## 为何选择 token 级奖励而不是序列级奖励？

<!-- footnote-right: 来源：[@dejavukun 在 YouTube 第三讲的评论](https://www.youtube.com/watch?v=K_Sj_-1BUMM&lc=Ugz9joGHibucDB5llqJ4AaABAg) -->

小心：这里有两个不同含义。

- **奖励粒度：** 最终答案奖励 vs 步骤/token 级奖励（PRM、KL 惩罚、格式奖励）[@lightman2023let]。
- **损失粒度：** 按序列平均 vs 按激活 token 平均；DAPO 使用 token 级策略梯度损失 [@yu2025dapo]。

```python
# Sequence-normalized: each completion has equal weight
loss = ((pg_loss * mask).sum(dim=1) / mask.sum(dim=1)).mean()

# Token-normalized: each generated token has equal weight
loss = (pg_loss * mask).sum() / mask.sum()
```

|||

Token 级奖励为何有帮助：
- 局部信号：KL 惩罚、格式奖励、PRM、部分分数
- 长思维链（long-CoT）强化学习：对实际采样到的 token 提供梯度
- 批处理：按激活 token 数归一化，而不是按样本数
- DAPO：token 级损失 + Clip-Higher + 推理强化学习的动态采样 [@yu2025dapo]

反驳观点：如果奖励只来自最终答案正确性，序列级优势仍然更自然；GSPO 将比例推回至序列级 [@zheng2025gspo]。

## GAE 是计算 PPO 中优势函数的唯一方式吗？

<!-- footnote-right: 来源：[GitHub issue #382](https://github.com/natolambert/rlhf-book/issues/382) -->

[PPO 裁剪目标函数](https://rlhfbook.com/rl-cheatsheet/)（参见速查表）：

$$J(\theta) = \mathbb{E}_t\!\left[\min\!\left(\rho_t(\theta)\hat{A}_t,\; \text{clip}(\rho_t(\theta),\, 1-\varepsilon,\, 1+\varepsilon)\hat{A}_t\right)\right]$$

不是！但据我所知，没有人使用其他方法，也没有人使用原始的值模型。GAE 行之有效。

## $\rho$ 的形状（shape）是什么？

<!-- footnote-right: 来源：[@JGLambourne 在 YouTube 第三讲的评论](https://www.youtube.com/watch?v=K_Sj_-1BUMM&lc=UgwC9D0I4zmtGtyyGz14AaABAg) -->

<!-- columns: 50/50 -->

## $\rho$ 的形状（shape）是什么？

<!-- footnote-right: 来源：[@JGLambourne 在 YouTube 第三讲的评论](https://www.youtube.com/watch?v=K_Sj_-1BUMM&lc=UgwC9D0I4zmtGtyyGz14AaABAg) -->

$$\rho_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_\text{old}}(a_t \mid s_t)}$$

- $\pi(\cdot \mid s_t)$ 是词表大小（vocab-shaped）：`[B, T, V]`
- $\pi(a_t \mid s_t)$ 是在采样到的 token 处 gather 得到的：`[B, T]`
- $\rho_t$ 是每个 token 的标量；rollout 张量的形状是 `[B, T]`

|||

```python
# logits/logprobs over vocab: [B, T, V]
old_logps_all = old_policy.log_softmax(logits_old, dim=-1)
new_logps_all = policy.log_softmax(logits_new, dim=-1)

# sampled token ids: [B, T]
actions = input_ids[:, 1:]

# gather only the probabilities of the sampled tokens: [B, T]
old_logps = old_logps_all.gather(-1, actions.unsqueeze(-1)).squeeze(-1)
new_logps = new_logps_all.gather(-1, actions.unsqueeze(-1)).squeeze(-1)

# importance ratio per sampled token: [B, T]
rho = torch.exp(new_logps - old_logps)
```

## 为什么 PPO 在策略和值函数损失上都使用 `torch.max`？

<!-- footnote-right: 来源：[@jacoboromerodiaz6967 在 YouTube 第四讲的评论](https://www.youtube.com/watch?v=i-AIMpZHgeg&lc=UgwjmSeeAuvtuN_B85R4AaABAg) -->

```python
# PPO minimizes a negative policy loss
pg_loss_unclipped = -advantages * ratio
pg_loss_clipped = -advantages * torch.clamp(
    ratio, 1.0 - eps, 1.0 + eps
)

# choose the more conservative / worse loss
pg_loss = torch.max(pg_loss_unclipped, pg_loss_clipped)
```

`torch.max` 之所以关键，是因为 PPO 写作**一个需要最小化的损失函数**。

它选出裁剪之后给出**更少改进**（即更保守）的那个更新。

|||

```python
# value clipping: do not let critic jump too far
v_clip = old_values + torch.clamp(
    v_pred - old_values, -vf_eps, vf_eps
)

vf_unclipped = 0.5 * (v_pred - targets) ** 2
vf_clipped = 0.5 * (v_clip - targets) ** 2

# optimize the worse value error
vf_loss = torch.max(vf_unclipped, vf_clipped)
```

策略裁剪限制了策略漂移。

值函数裁剪限制了 critic 漂移。

相同的模式：比较未裁剪和裁剪后的值，训练上表现更差（更大）的那个。
